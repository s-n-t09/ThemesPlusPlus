How Themes++ works

Themes++ is a repair-focused continuation of Themes+, designed for Revenge, Kettu, and other Discord clients derived from Vendetta. This page explains every supported feature and the compatibility repairs made for modern Discord builds.

Overview

The active Discord theme remains the source of theme-specific data. When a theme exposes the Themes+ data format, Themes++ reads its enhancement settings and applies the available patches without replacing the theme itself. If the theme does not define an iconpack, the plugin falls back cleanly and still attempts the other supported enhancements.

The plugin stores its preferences in the client’s plugin storage. Settings are kept across restarts, while the runtime state is rebuilt whenever the plugin loads, the user changes an iconpack mode, or the active configuration is reloaded.

Features

Theme-aware icon colors

Themes++ applies the icon color information provided by the active theme to Discord image and icon elements. It preserves the original dimensions and rendering properties, so recolored icons continue to behave like the client’s original assets.

Theme colors and mention-line customization

When the theme provides the corresponding enhancement data, Themes++ patches the message mention-line colors and related theme-defined visual values. This is kept separate from iconpack loading, which means a missing iconpack does not unnecessarily disable the other color enhancements.

Custom icon overlays

Legacy Discord check and radio assets can receive the custom overlay images described by the theme. The overlay renderer is compatible with both the older interception path and the modern element-creation path. Themes++ also recognizes compatible legacy theme data when the newer explicit overlay flag is absent.

Automatic, manual, and disabled iconpack modes

Automatic follows the iconpack selected by the active theme. Manual displays the maintained iconpack index and lets the user choose a specific pack. Disabled keeps Discord’s default icons while allowing other theme enhancements to remain active.

Custom iconpack URLs

Custom mode accepts a base URL containing an iconpack’s files. The trailing slash is optional. A filename suffix can be added for legacy iOS-style packs, while modern packs normally use an empty suffix. The settings screen includes a live preview URL so an incorrect base path can be spotted before relying on the pack.

Iconpack caching and graceful fallbacks

The iconpack index, configuration, and file tree are fetched independently. Successful responses are cached locally, so a temporary network failure can continue using the last known data. If a selected pack cannot be resolved, Themes++ leaves the original Discord asset in place instead of breaking the entire settings or rendering flow.

Manual list refresh behavior

In Manual mode, the iconpack list remains available even when Custom is selected. Changing between a bundled pack and Custom immediately updates the stored selection, reloads the enhancement state, and refreshes the settings view when asynchronous data arrives.

How iconpack replacement works

For each image-like element, Themes++ tries to identify the source asset. It supports numeric registry IDs, source objects, source arrays, Vendetta-provided icon URIs, and modern Discord asset metadata. The resolver extracts the asset name and available module information, then compares normalized candidates against the selected iconpack’s file tree.

Matching supports modern Discord paths such as design/components/Icon/native/redesign/generated/images/, common native image paths, external Vendetta paths, normalized separators, optional leading directories, and legacy filename suffixes. When a match is found, only the image source is replaced with the corresponding iconpack URL. Other image properties are retained.

Because the iconpack tree is authoritative for the selected pack, Themes++ does not assume that every pack uses the same directory layout. This is why paths are normalized and checked through several safe candidates instead of relying on one hardcoded folder.

Repairs applied to Themes+

React Native function-component compatibility

Modern Discord builds converted many image and icon paths to React function components. The older Themes+ approach primarily modified the legacy RN.Image rendering boundary. A function component could capture its original image reference before that modification, so the old patch would not reach it.

Themes++ keeps the legacy path for older clients and adds interception at the React element boundary. It observes React.createElement, jsx, and jsxs when those runtime functions are available. The source is transformed before React Native renders the element, which restores iconpack replacement for native Discord icons while retaining compatibility with Vendetta-related icons.

Stable plugin storage

The settings UI and loader now use a dedicated storage module backed directly by the Vendetta plugin storage API. This avoids a circular entrypoint dependency that could produce Property 'vstorage' doesn't exist when opening Manual and then Custom on some clients.

Asynchronous settings updates

The settings screen subscribes to the plugin’s runtime state. When the iconpack index finishes loading, the Manual list is rendered immediately instead of waiting for a manual refetch or reopening the screen. Mode and pack changes also trigger a new load so the selected visual configuration is applied without stale state.

Modern package delivery

The repository publishes a valid root-level package containing manifest.json and the declared index.js. The same GitHub Pages root URL serves a human-readable installation page in a browser and a valid Vendetta-compatible package to the plugin manager.

Troubleshooting

If a pack appears enabled but one icon remains unchanged, that asset may not exist in the selected pack’s file tree. The safe fallback is intentional. Try another pack, verify the custom base URL using the preview, or check that the suffix matches the pack’s naming convention.

If the Manual list is empty, remain in Manual mode for a moment while the index loads. A successful response is cached locally. If a previous client version still serves an older plugin bundle, use the client’s normal plugin refetch or update action once, then reopen the settings panel.

Client internals can change between Discord releases and mod builds. Themes++ targets the standard Vendetta-compatible APIs and includes fallbacks, but a future internal change may require another compatibility update.
